Phase 00

Présentation du challenge

📜 ÉNONCÉ OFFICIEL

Une session d'authentification twitter a été capturée. Retrouvez le mot de passe de l'utilisateur dans cette capture réseau.

Fichier fourni : un fichier pcap contenant une seule trame : une requête HTTP envoyée vers twitter.com.
Contrairement aux challenges Kerberos/NTLM où il faut casser un hash, ici le mot de passe est directement lisible dans la capture — à condition de savoir où regarder et de comprendre le mécanisme d'authentification utilisé.

Phase 01

Vocabulaire clé

pcap
Packet Capture — fichier contenant des trames réseau capturées, analysable avec Wireshark, tshark, tcpdump.
HTTP
HyperText Transfer Protocol — protocole applicatif du Web, fonctionnant en clair (d'où l'existence de HTTPS).
Authorization
En‑tête HTTP utilisé pour transmettre des identifiants d'authentification.
Basic Authentication
Mécanisme HTTP le plus simple : le client envoie utilisateur:motdepasse encodé en base64.
Base64
Encodage binaire→ASCII sur 64 caractères (RFC 4648). C'est un encodage, pas un chiffrement : trivialement réversible.
Follow TCP Stream
Fonction Wireshark qui reconstitue le flux complet d'une connexion TCP en clair.
Phase 02

Théorie : l'authentification HTTP Basic

Principe

Ordinogramme — Échange HTTP Basic 1. Client demande ressource protégée → 2. Serveur → 401 Unauthorized → 3. Client renvoie Authorization: Basic base64(user:pass) → 4. Serveur valide et répond

La chaîne envoyée est utilisateur:motdepasse encodée en base64. Le base64 ne fait que transformer des octets en caractères imprimables (pour traverser des protocoles historiquement 7‑bits). Il n'y a ni clé, ni secret : n'importe qui peut décoder. Et surtout, sur du HTTP pur (non chiffré), toute la requête — y compris l'en‑tête Authorization — circule en clair sur le réseau : n'importe quel observateur (Wireshark, tcpdump, point d'accès Wi‑Fi, routeur) peut la lire.

« Encodé » ≠ « Chiffré »
Basic auth + HTTP = identifiants équivalents à du texte brut. C'est exactement le piège de ce challenge : le mot de passe est « caché » derrière du base64, ce qui n'est qu'une illusion de sécurité.

Phase 04

Extraction du mot de passe

Méthode 1 — Wireshark (la plus simple)

Dans le panneau des détails, déplier : Hypertext Transfer Protocol → Authorization: Basic dXNlcnRlc3Q6cGFzc3dvcmQ= Wireshark affiche automatiquement le champ dérivé : 

Credentials: usertest:password

Ou, plus visuel : clic droit sur la trame → Follow → TCP Stream, et lire l'en‑tête Authorization directement dans le flux reconstitué.

Méthode 2 — Décodage base64 (pédagogique)

Le champ Authorization suit le format Basic <base64(utilisateur:motdepasse)>. Récupérons la chaîne et décodons‑la :

Commande base64
echo 'dXNlcnRlc3Q6cGFzc3dvcmQ=' | base64 -d
Résultat
usertest:password

Vérifions le découpage, champ par champ : 

| Élément      | Valeur base64       | Décodé      |
|--------------|---------------------|-------------|
| Utilisateur  | dXNlcnRlc3Q=        | usertest    |
| Séparateur   | Og==                | :           |
| Mot de passe | cGFzc3dvcmQ=        | password    |
| Total        | dXNlcnRlc3Q6cGFzc3dvcmQ= | usertest:password |

On peut aussi vérifier l'encodage :

Vérification
echo -n 'usertest:password' | base64
# dXNlcnRlc3Q6cGFzc3dvcmQ=

Méthode 3 — tshark (ligne de commande)

Commande tshark
tshark -r ch3.pcap -Y "http.authorization" -T fields -e http.authorization
# Basic dXNlcnRlc3Q6cGFzc3dvcmQ=

Phase 06

Enjeux de sécurité (côté SOC)

La méthode en 4 étapes (à retenir)

Processus de résolution 1. Ouvrir le pcap → 2. Identifier HTTP (port 80) → 3. Repérer l'en‑tête Authorization → 4. Décoder le base64

Le message de sécurité

Ce challenge, vieux de plus de 15 ans, illustre trois leçons toujours d'actualité :

HTTP en clair = tout est lisible
Requête, en‑têtes, cookies et identifiants traversent le réseau en texte brut. Un observateur passif (Wi‑Fi public, mirror de port, MITM) lit tout sans effort.
Base64 ≠ chiffrement
Encoder n'apporte aucune confidentialité. Les identifiants en Basic auth sont équivalents à du clair — Wireshark les affiche d'ailleurs directement.
Basic auth à proscrire
Ne jamais utiliser Basic auth sans TLS. Même avec HTTPS, le couple utilisateur:motdepasse est rejouable (pas de nonce).

Recommandations

  • 01
    Chiffrer les transports — HTTPS obligatoire (HSTS), interdire le HTTP clair pour toute authentification.
  • 02
    Remplacer Basic auth — utiliser OAuth 2.0 / Bearer tokens / mTLS, avec des tokens courts et révocables.
  • 03
    Ne pas réutiliser de secrets — le mot de passe password est un exemple parfait de ce qu'il ne faut jamais faire.
  • 04
    Détection — règles SIEM/Sigma sur les en‑têtes Authorization: Basic non accompagnés de TLS, et sur le HTTP clair transportant des identifiants.

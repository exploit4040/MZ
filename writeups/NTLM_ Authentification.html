Phase 00

Présentation du challenge

📜 ÉNONCÉ OFFICIEL

Vous êtes mandaté par l'équipe SOC de l'entreprise Cat Corporation pour retrouver le mot de passe d'un utilisateur lié à une connexion NTLM over SMB suspecte.
Format du flag : RM{userPrincipalName:password} — l'userPrincipalName doit être écrit en minuscules.

Fichier fourni : une capture réseau (pcap) contenant une authentification NTLMv2 complète sur SMB.

Phase 01

Vocabulaire clé NTLM

NTLM
NT LAN Manager — protocole d'authentification challenge‑response de Microsoft, encore utilisé pour la rétrocompatibilité.
NetNTLMv2
Version 2 du challenge‑response. Le client prouve qu'il connaît le mot de passe sans jamais l'envoyer sur le réseau.
SMB
Server Message Block — protocole de partage de fichiers Windows (port 445), vecteur fréquent de NTLM.
NTLMSSP
NTLM Security Support Provider — encapsule les messages NTLM dans SPNEGO/GSS‑API.
Challenge
Nombre aléatoire de 8 octets généré par le serveur et envoyé au client.
NT hash
MD4( UTF-16LE( mot_de_passe ) ) — l'empreinte stockée dans la SAM ou ntds.dit.
NTProofStr
HMAC‑MD5( Clé_NTLMv2, challenge_serveur + blob ) — la preuve cryptographique envoyée au serveur.
Blob
Structure NTLMv2 contenant le client challenge, l'horodatage et les AV‑pairs.
SPNEGO
Simple and Protected GSS‑API Negotiation — enveloppe négociant le mécanisme (ici NTLMSSP).
Phase 02

Théorie du handshake NTLMv2

Les 3 messages

Ordinogramme — NTLM handshake 1. NEGOTIATE (Type 1) → 2. CHALLENGE (Type 2) → 3. AUTHENTICATE (Type 3) → 4. STATUS_SUCCESS

Dans l'étape 2, le serveur envoie un challenge aléatoire de 8 octets. Le client calcule alors le NTProofStr à partir de ce challenge, du mot de passe, et d'un blob qu'il construit (client challenge, timestamp, informations de domaine). L'ensemble (NTProofStr + blob) est envoyé dans le message Type 3.

Chaîne de calcul de la preuve
NT hash = MD4( UTF‑16LE( mot_de_passe ) )
Clé NTLMv2 = HMAC‑MD5( NT_hash, user_MAJUSCULES + domaine_MAJUSCULES )
NTProofStr = HMAC‑MD5( Clé_NTLMv2, challenge_serveur + blob )

Le point crucial : tout ce qui circule est en clair (sauf le mot de passe lui‑même). Le challenge, le NTProofStr et le blob sont visibles dans le pcap. On peut donc casser hors ligne : pour chaque mot de passe candidat, on refait la chaîne de calcul et on compare le NTProofStr obtenu. C'est le principe du mode hashcat 5600.

Phase 04

Construction du hash (mode 5600)

Le format attendu par hashcat est :

Syntaxe NetNTLMv2
USERNAME::DOMAIN:SERVER_CHALLENGE:NT_PROOF:NTLM_RESPONSE_BLOB
⚠️ Piège n°1 : le blob doit être sans les 16 premiers octets (le NTProofStr). Ne pas copier la NTLMv2 Response complète.
⚠️ Piège n°2 : la double paire de deux‑points :: après l'utilisateur (champ « hostname » vide) est obligatoire.

Phase 05

Cracking avec hashcat (sortie réelle commentée)

Commande lancée

Ligne de commande
hashcat -m 5600 hash.txt /home/spectrax/Documents/wordlis/rockyou.txt

Déroulé commenté

1. Initialisation OpenCL

OpenCL API (OpenCL 3.0 PoCL 7.0 Linux ...) - Platform #1 [The pocl project]
* Device #1: cpu-haswell-Intel(R) Core(TM) i5-6300U CPU @ 2.40GHz, 5850/11764 MB, 4MCU

hashcat utilise le CPU (i5-6300U) via OpenCL (backend PoCL). Aucun GPU n'est détecté — la vitesse est modeste (232 kH/s) mais plus que suffisante pour ce challenge.

2. Analyse du hash

Hashes: 1 digests; 1 unique digests, 1 unique salts
Optimizers applied:
* Zero-Byte / Not-Iterated / Single-Hash / Single-Salt

Not-Iterated : NetNTLMv2 n'est pas un hash itératif (contrairement à bcrypt ou PBKDF2), donc le crack est très rapide. Single-Hash indique qu'un seul hash est chargé.

3. Avertissement « Pure kernel »

ATTENTION! Pure (unoptimized) backend kernels selected.
Pure kernels can crack longer passwords, but drastically reduce performance.
If you want to switch to optimized kernels, append -O to your commandline.

Sans l'option -O, hashcat utilise les kernels purs qui supportent des mots de passe jusqu'à 256 caractères mais sont plus lents. Pour ce challenge, le crack est quasi instantané, donc cela n'a pas d'impact.

4. Chargement de la wordlist

Dictionary cache built:
* Filename..: /home/spectrax/Documents/wordlis/rockyou.txt
* Passwords.: 14344392
* Bytes.....: 139921507

rockyou.txt : 14 344 392 entrées. C'est la wordlist de référence issue du vol du site RockYou (2009), contenant des millions de mots de passe réels.

6. Vérification avec --show

Commande de vérification
hashcat -m 5600 hash.txt --show

Cette commande lit le potfile (~/.local/share/hashcat/hashcat.potfile) et affiche le résultat sans relancer l'attaque. La sortie est : 

john.doe::catcorp.local:1944952f5b845db1:5c336c6b69fd2cf7b64eb0bde3102162:01010000000000001a9790044b63da...:rootbeer

Pourquoi le mode 5600 ?

| Mode | Type           | Origine                           |
|------|----------------|-----------------------------------|
| 1000 | NT hash (MD4)  | Dump SAM / ntds.dit               |
| 5500 | NetNTLMv1      | Capture réseau (Responder)        |
| 5600 | NetNTLMv2      | Capture réseau (Responder) ← nous |
| 3000 | LM hash        | Anciens systèmes                  |

La structure user::domaine:challenge:proof:blob est la signature du NetNTLMv2 → mode 5600.

Phase 06

Flag & recommandations de sécurité

L'énoncé demande : RM{userPrincipalName:password} avec l'userPrincipalName en minuscules.

  • userPrincipalName : john.doe@catcorp.local
  • password : masqué pour préserver l'intérêt du challenge
Flag final (masqué partiellement)
RM{john.doe@catcorp.local:*******}
⚠️ Piège n°3 : beaucoup de joueurs échouent en écrivant le domaine en majuscules ou en omettant @catcorp.local. L'UPN exact est john.doe@catcorp.local en minuscules.

Recommandations pour Cat Corporation

  • 01
    Désactiver NTLM : Restreindre NTLM via GPO (*Network security: Restrict NTLM*) là où Kerberos est possible.
  • 02
    Politique de mots de passe : exiger des mots de passe longs (>15 caractères) et interdire les mots de wordlists via les filtres de bloat AD.
  • 03
    MFA : Déployer Windows Hello for Business ou Azure AD MFA pour neutraliser l'impact d'un mot de passe compromis.
  • 04
    Contrer Responder : Désactiver LLMNR et NBT-NS (GPO), activer la signature SMB obligatoire.
  • 05
    Détection : Règles SIEM/Sigma sur les événements 4624 (LogonType 3) depuis des sources inhabituelles, rafales d'échecs 4771/4776.
